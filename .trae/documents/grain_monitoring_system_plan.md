# 粮库温湿度监控预警系统的设计与实现计划书

本计划书旨在为“基于 Spring Boot 的粮库温湿度监控预警系统”提供一套完整的设计与实现方案。该系统旨在通过实时监控粮库环境数据，实现异常预警，提升仓储管理智能化水平。

## 1. 项目概述
本系统将采用前后端分离架构，通过对接 MQTT 协议的温湿度传感器，实现数据的实时采集、处理与可视化展示。

### 1.1 技术栈选择
- **后端**：Spring Boot 3.x, MyBatis-Plus, MySQL 8.0, MQTT (Eclipse Paho), WebSocket, Spring Security.
- **前端**：Vue 3 (Composition API), Vite, Element Plus, ECharts, Axios, Pinia.
- **协议**：MQTT (用于设备通信), WebSocket (用于实时数据推送).

## 2. 核心功能设计

### 2.1 后端模块
- **设备接入模块**：负责监听 MQTT 主题，解析传感器上报的 JSON 数据（设备ID、温度、湿度、时间戳等）。
- **数据处理模块**：对采集到的原始数据进行清洗、阈值校验，触发预警逻辑。
- **存储模块**：将历史监测数据存储至 MySQL 数据库，支持高效查询。
- **预警中心**：当数据超过预设阈值时，生成预警记录，并通过 WebSocket 实时推送到前端。
- **系统管理**：包括设备管理（增删改查）、预警阈值设置、用户信息管理。

### 2.2 前端模块
- **实时监控大屏**：利用 ECharts 展示温湿度实时变化曲线。
- **设备管理界面**：展示所有监测点状态（在线/离线），支持设备参数配置。
- **历史记录查询**：支持按时间段、设备ID查询温湿度历史数据及预警信息。
- **预警设置中心**：用户可自定义每个监测点的温湿度上下限报警阈值。

## 3. 数据库设计 (MySQL)
### 3.1 主要数据表
- `device_info`：存储传感器 ID、位置、安装时间、状态等。
- `sensor_data`：存储历史温湿度记录（ID, device_id, temperature, humidity, timestamp）。
- `alarm_config`：存储每个监测点的预警阈值（ID, device_id, max_temp, min_temp, max_hum, min_hum）。
- `alarm_log`：存储预警触发记录（ID, device_id, type, value, timestamp, status）。
- `user`：存储管理人员账户信息。

## 4. 实施步骤

### 阶段一：后端核心架构搭建
1. 初始化 Spring Boot 项目，配置 MyBatis-Plus 和 MySQL 连接。
2. 编写实体类（Entity）、Mapper 接口及基础 CRUD 服务。
3. 集成 MQTT 客户端，实现订阅特定主题并解析传感器数据的逻辑。
4. 实现 WebSocket 服务端，用于向前端推送实时消息。

### 阶段二：前端界面开发
1. 初始化 Vue 3 + Vite 项目，配置 Element Plus 组件库。
2. 设计响应式布局，搭建基础路由框架（Dashboard, Device, Alarm, History）。
3. 集成 ECharts，编写通用的图表组件用于数据展示。
4. 对接后端 API 接口，实现数据的动态加载与展示。

### 阶段三：功能集成与联调
1. 联调 MQTT 模拟器与后端，验证数据采集流程。
2. 测试 WebSocket 实时推送功能，确保前端能即时响应预警。
3. 完善异常处理机制，增加系统日志记录。

### 阶段四：测试与优化
1. 进行压力测试，确保多点并发数据接入时的系统稳定性。
2. 优化数据库索引，提升大数据量下的历史数据查询速度。
3. UI 细节调整，提升用户交互体验。

## 5. 预期成果
- 一个稳定运行的 Spring Boot 后端服务，具备高并发处理传感器数据的能力。
- 一个现代化的 Vue 3 前端界面，提供直观的温湿度监控与预警管理功能。
- 完整的数据库设计，支持百万级监控数据的持久化存储与分析。
